# زبرسنگری — فعال‌سازی پنل واقعی (نسخه آزمایشی امن)

**وضعیت:** این قابلیت فعلاً فقط روی شاخه \`feature/secure-admin\` است؛ به سایت اصلی منتشر نشده. تا انجام مراحل زیر شاخه را Merge نکنید.

## ۱. ساخت KV رایگان برای تصاویر

1. Cloudflare Dashboard → **Storage & databases → KV**.
2. روی **Create namespace** بزنید.
3. نام: \`zebarsangari-images\`.
4. پس از ساخت، **Namespace ID** را یادداشت کنید. این شناسه را می‌توان برای اتصال مخزن ارسال کرد؛ **API Token و رمز نفرستید**.
5. فایل \`wrangler.kv.example.jsonc\` الگوی اتصال است. شناسه واقعی باید در \`wrangler.jsonc\` با \`binding: "IMAGES"\` قرار بگیرد.
6. حجم رایگان KV در زمان نگارش 1 GB ذخیره‌سازی، 1000 نوشتن و 100,000 خواندن در روز است؛ استفاده بیشتر باید جداگانه بررسی شود.

## ۲. جدول امنیت ورود D1

در Console دیتابیس \`zebarsangari-db\`، دستورات زیر را اجرا کنید:

\`\`\`sql
CREATE TABLE IF NOT EXISTS admin_login_attempts (
 ip_hash TEXT PRIMARY KEY,
 failure_count INTEGER NOT NULL DEFAULT 0 CHECK(failure_count >= 0),
 window_start_ms INTEGER NOT NULL DEFAULT 0,
 blocked_until_ms INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_admin_login_blocked ON admin_login_attempts(blocked_until_ms);
\`\`\`

این فقط شمارنده تلاش‌های ورود را ذخیره می‌کند، نه رمز عبور یا آدرس IP خام.

## ۳. دو رمز محرمانه در Cloudflare

در Workers & Pages → zebarsangari-shop → Settings → Variables and Secrets دو **Secret** تعریف کنید:

- \`ADMIN_PASSWORD\` — رمز قوی و منحصربه‌فرد مدیر (ترجیحاً حداقل ۲۰ کاراکتر). این رمز را فقط در Cloudflare وارد کنید.
- \`SESSION_SECRET\` — رشته تصادفی حداقل ۳۲ کاراکتر (ترجیحاً ۶۴ کاراکتر تصادفی). برای امضای نشست ورود استفاده می‌شود.

**هرگز این مقدارها را در GitHub، اسکرین‌شات یا گفت‌وگو ارسال نکنید.** اگر Secretها تنظیم نباشند، پنل با پاسخ 503 بسته می‌ماند.

## ۴. مرحله انتشار و تست (فقط بعد از ۱،۲،۳)

پس از آماده بودن D1، KV و Secretها، شاخه امن باید پس از بررسی روی \`main\` ادغام شود تا Cloudflare آن را منتشر کند. پیش از ادغام، آزمایش امنیت و کاربردپذیری لازم است.

- \`/manage.html\` پنل واقعی است؛ \`/admin.html\` پس از انتشار به این صفحه هدایت می‌شود.
- ورود تنها با رمز مدیر انجام می‌شود؛ نشست دارای Cookie امن HttpOnly و محدودیت زمانی است.
- اضافه/ویرایش محصول، قیمت به تومان، موجودی هر سایز و رنگ، غیرفعال‌سازی، بارگذاری تصویر فشرده‌شده و حذف تصویر در نظر گرفته شده است.
- مسیرهای \`/api/admin/*\` برای عملیات نوشتن به ورود و CSRF نیاز دارند.
- تصاویر در KV تحت \`IMAGES\` ذخیره می‌شوند؛ اطلاعاتشان در D1 است.
- **پرداخت، ثبت سفارش، ثبت‌نام مشتری و اتصال خودکار ویترین اصلی هنوز پیاده‌سازی نشده‌اند.**
- صفحه اصلی همچنان نمونه محصولات را نشان می‌دهد؛ قبل از پذیرش مشتری باید ویترین با API داده واقعی همگام شود.

## ایمنی و محدودیت‌های آزمایشی

- پشتیبان دیتابیس، قیمت‌گذاری، قوانین ارسال/مرجوعی، کنترل موجودی هنگام سفارش و درگاه پرداخت باید قبل از بهره‌برداری واقعی تکمیل شوند.
- تصاویر آپلودی باید حق استفاده تجاری داشته باشند. فایل‌ها روی مرورگر به WebP فشرده می‌شوند و محدودیت 650 KB سمت سرور اعمال می‌شود.
- وجود طرح روی GitHub به معنی تست/انتشار نهایی نیست؛ قبل از فعال‌سازی، اتصال و دسترسی از داخل ایران باید دوباره آزمایش شود.
