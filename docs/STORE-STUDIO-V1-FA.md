# زبرسنگری — استودیو مدیریت ویترین (نسخه ۱)

هدف: ساخت یک پنل فارسی و ساده برای مدیریت رتبه دسته‌ها، دسته و زیردسته، عضویت چندگانه محصولات، محصول ویژه و ترتیب بخش‌های صفحه اصلی؛ بدون خرید نرم‌افزار یا هاست جدید.

## آدرس پنل
بعد از Deploy: `https://zebarsangari-shop.yahyaelahimiavagh.workers.dev/studio.html`
ورود با **همان رمز مدیریت فعلی**، از `ADMIN_PASSWORD` و `SESSION_SECRET` در Cloudflare.
هنگام ویرایش قیمت، عکس، رنگ و سایز، لینک «مدیریت محصولات» به `/manage.html` می‌رود.

## گام ضروری: Migration دیتابیس (قبل از استفاده)
به **Cloudflare → D1 → zebarsangari-db → Console** برو.
فایل `migrations/0005_store_studio.sql` را از GitHub باز کن و **تمام متن SQL** را در Console اجرا کن.
این عملیات additive است: جدول‌های فعلی محصولات/سفارش و رسیدهای قدیمی را پاک نمی‌کند.

جداول تازه:
- `shop_categories`: عنوان فارسی، والد، رتبه و وضعیت نمایش؛ ۵ دسته اصلی قبلی ایجاد می‌شوند.
- `shop_product_categories`: محصول می‌تواند در چند دسته باشد؛ دسته محصولات قبلی به شکل خودکار وارد می‌شود.
- `shop_product_display`: رتبه و وضعیت «ویژه».
- `shop_home_sections`: ترتیب و وضعیت نمایش بخش‌های صفحه اصلی.

بعد از اجرا، بررسی:
```sql
SELECT name FROM sqlite_master WHERE type='table'
AND name IN ('shop_categories','shop_product_categories','shop_product_display','shop_home_sections')
ORDER BY name;
```
باید دقیقاً ۴ ردیف دریافت شود.

تا قبل از اجرای Migration، سایت همچنان کاتالوگ قدیمی را نمایش می‌دهد، اما بخش جدید مدیریت با پیام `migration_required` کار نمی‌کند. **روی سایت اصلی بدون Migration قابل استفاده نیست.**

## امکانات نسخه اول
۱. ساخت دسته و زیردسته با عمق محدود برای جلوگیری از درخت حلقوی، تغییر نام، مخفی کردن، حذف دسته خالی.
۲. رتبه‌بندی دسته‌ها با فلش‌های بالا/پایین در موبایل و Drag & Drop در دسکتاپ؛ جابه‌جایی فقط در یک سطح والد.
۳. فهرست محصولات فعلی با جست‌وجو؛ رتبه‌بندی دستی، تعیین محصول ویژه، عضویت در چند دسته.
۴. تعیین ترتیب و نمایش/عدم نمایش «دسته‌بندی‌ها»، «محصولات»، «مجموعه‌های منتخب»، «مزایای خرید»، «درباره فروشگاه»؛ ذخیره در دکمه «انتشار چیدمان».
۵. ویترین ترتیب و دسته‌ها را از D1 می‌خواند و محصول را در دسته‌های جدید نمایش می‌دهد. محصولاتی که هنوز در جدول عضویت جدید ثبت نشده‌اند، با دسته قبلی نمایش داده می‌شوند.

## مواردی که هنوز باید توسعه داده شوند
- ساخت و ویرایش همه مشخصات محصول (عکس، سایز، رنگ، قیمت و موجودی) هنوز در پنل قدیمی است؛ این نسخه **جایگزین کامل پنل مدیریت محصولات نیست**.
- حداکثر ۱۵۰ محصول در API عمومی و ۳۰۰ محصول در لیست استودیو نمایش داده می‌شود. فروشگاه‌های بزرگ‌تر به Pagination و جست‌وجوی سروری نیاز دارند.
- بنرهای چندعکسی قابل‌ویرایش و تعیین ترتیب عکس‌ها هنوز در این مرحله نیستند.
- Drag & Drop لمسی برای گوشی ندارد؛ برای موبایل از دکمه‌های جابه‌جایی استفاده کن.
- پنهان‌کردن یک دسته فقط آن دسته را از فهرست دسته‌ها برمی‌دارد و **محصولات آن را از «همه محصولات» حذف نمی‌کند**.
- محصول «ویژه» با برچسب در کارت محصول نمایش داده می‌شود؛ بخش جداگانه محصولات ویژه هنوز ساخته نشده است.
- قبل از انتشار واقعی، باید در گوشی و دسکتاپ تست انسانی انجام شود. تست‌های فعلی شامل Syntax، یکپارچگی API و شبیه‌سازی Migration در SQLite هستند.

## تست امن
- از دیتابیس بکاپ بگیر.
- اجرا Migration روی D1؛ چک چهار جدول.
- در `/studio.html` ورود مدیر.
- یک زیردسته آزمایشی «سوتین» برای «زنانه» ایجاد کن، ترتیب آن را تغییر بده.
- محصول فعلی را در دو دسته قرار بده و «ویژه» کن.
- در صفحه اصلی، محصول و دسته را پیدا کن؛ تغییر ترتیب باید اعمال شده باشد.
- بخش «درباره ما» را موقتاً مخفی و سپس دوباره نمایش بده.
- تا پایان تست، سفارش واقعی را غیرفعال نگه دار. نیازی به تغییر رمز یا انتشار شماره کارت نیست.

## امنیت و هزینه
- همان کوکی `HttpOnly`، رمز مدیریت و CSRF قبلی برای همه نوشتن‌های Studio استفاده می‌شود.
- داده‌ها در D1 ذخیره می‌شوند؛ هیچ API خارجی و سرویس پولی جدیدی اضافه نشده است.
- صفحه Studio با `no-store` و CSP مدیریت سرو می‌شود.
