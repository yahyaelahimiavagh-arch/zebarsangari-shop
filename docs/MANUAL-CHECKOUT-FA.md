# زبرسنگری — پرداخت دستی و ارسال رسید از پیام‌رسان‌ها

## روند فعلی

1. مشتری محصول، رنگ و سایز را انتخاب می‌کند و وارد **تکمیل خرید** می‌شود.
2. شماره کارت، نام صاحب کارت، نام بانک و دکمه کپی **فقط در تکمیل خرید** نمایش داده می‌شوند؛ در صفحه عمومی محصولات و فوتر نمایش داده نمی‌شوند.
3. درخواست سفارش در D1 ثبت می‌شود؛ جمع کالاها از دیتابیس محاسبه شده و وضعیت اولیه `pending` است.
4. مشتری پس از هماهنگی هزینه ارسال و پرداخت، کد سفارش و تصویر رسید را در **واتساپ، تلگرام یا بله** به فروشنده می‌فرستد.
5. **هیچ فایل رسیدی به Cloudflare ارسال یا در KV ذخیره نمی‌شود.** مسیر قدیمی `/api/orders/<id>/receipt` اکنون کد 410 می‌دهد و دکمه آپلود حذف شده است.
6. فروشنده با دیدن پیام و بررسی گردش بانک، وضعیت سفارش را در پنل مدیریت تغییر می‌دهد؛ باز شدن پیام‌رسان تأیید پرداخت نیست.

## تنظیم جدید بله

برای اضافه‌کردن مشخصات بله باید ابتدا در **Cloudflare → D1 → zebarsangari-db → Console** این migration را اجرا کنید:

```sql
CREATE TABLE IF NOT EXISTS shop_bale_settings (
  id INTEGER PRIMARY KEY CHECK(id=1),
  bale_phone TEXT NOT NULL DEFAULT '',
  bale_username TEXT NOT NULL DEFAULT '',
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now'))
);
INSERT OR IGNORE INTO shop_bale_settings(id) VALUES (1);
```

سورس: [migrations/0004_bale_settings.sql](../migrations/0004_bale_settings.sql)

بعد از اجرای موفق، در `/manage.html`:
- «شماره تلفن بله»: شماره ثبت‌شده در بله با فرمت `0912...` یا `+98912...`.
- «شناسه بله»: اختیاری و بدون `@`؛ اگر تنظیم شود، دکمه رسید مستقیم به `https://ble.ir/USERNAME` می‌رود.
- فقط با شماره تلفن و بدون شناسه، کاربر می‌تواند شماره را کپی کند و از داخل بله مخاطب فروشگاه را پیدا کند. لینک مستقیم معتبر از خود شماره ساخته نمی‌شود.
- اطلاعات واتساپ و تلگرام نیز همچنان قابل‌ویرایش‌اند.

در صورت اجرا نشدن migration، دیگر تنظیمات فعلی فروشگاه کار می‌کنند؛ اما ذخیره شماره یا شناسه بله با خطای مشخص رد می‌شود و به‌طور خاموش ذخیره نخواهد شد.

## تست بدون واریز واقعی

- آخرین Deployment را بررسی کنید. وارد پنل شده و شماره و شناسه بله را ذخیره کنید.
- سبد آزمایشی بسازید. کارت نباید در فوتر نمایش داده شود؛ باید در صفحه `/checkout.html` دیده شود.
- پس از ثبت سفارش آزمایشی، لینک‌های واتساپ، تلگرام و بله و کپی متن سفارش را تست کنید.
- عکس رسید را در وب‌سایت نمی‌توان انتخاب یا بارگذاری کرد؛ ارسال عکس فقط در خود پیام‌رسان و با انتخاب دستی کاربر انجام می‌شود.
- تلاش برای درخواست `POST /api/orders/<uuid>/receipt` باید پاسخ `410` بدهد.
- سفارش نباید صرفاً با بازکردن پیام‌رسان «تأیید شده» تلقی شود.
- از اطلاعات مشتری و شماره بانکی واقعی برای آزمون استفاده نکنید.

## حفاظت از اطلاعات

- **کارت فروشگاه در صفحه تکمیل خرید عمومی است** و شماره بله/واتساپ/تلگرام نیز برای مخاطبان سایت نمایش داده می‌شوند؛ فقط اطلاعات مورد موافقت مالک فروشگاه ثبت شود.
- تصویر رسید در **فضای ذخیره‌سازی این سایت** نگهداری نمی‌شود، اما در پیام‌رسان انتخاب‌شده ممکن است طبق سیاست آن سرویس ذخیره شود.
- **نام، شماره مشتری، آدرس و سفارش‌ها همچنان در D1 نگهداری می‌شوند**؛ سیاست حریم خصوصی، زمان حذف داده و دسترسی مدیر باید پیش از استفاده واقعی نهایی شود.
- اگر در نسخه‌های پیشین رسیدی در KV ذخیره شده باشد، این تغییر آن فایل قدیمی را خودکار حذف نمی‌کند؛ پاک‌سازی جداگانه باید با اطلاع مالک بررسی شود.
- برای فروش واقعی، شرایط ارسال/مرجوعی و تأیید دستی تراکنش بانکی ضروری‌اند.
