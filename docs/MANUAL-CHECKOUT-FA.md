# زبرسنگری — سفارش دستی واتساپ/تلگرام/کارت‌به‌کارت (نسخه آزمایشی)

**وضعیت:** کد فقط در شاخه `feature/manual-checkout` است. فعال‌سازی پیش‌فرض سفارش = خاموش.

## ۱. D1 migration ضروری

در **Cloudflare → D1 → zebarsangari-db → Console**، محتوای کامل فایل
[`migrations/0003_manual_checkout.sql`](../migrations/0003_manual_checkout.sql)
را اجرا کنید. بعد اجرای آن، جدول‌های زیر باید وجود داشته باشند:

- `shop_settings`
- `manual_orders`
- `manual_order_lines`
- `manual_order_rate`

بررسی: `SELECT name FROM sqlite_master WHERE type='table' AND name IN ('shop_settings','manual_orders','manual_order_lines','manual_order_rate');`

**بدون اجرای migration، این شاخه نباید به main ادغام شود.**

## ۲. تنظیم اطلاعات در پنل

پس از انتشار نسخه آزمایشی:
- در `/manage.html`، شماره واتساپ با فرمت **98912...**، نام کاربری تلگرام **بدون @**، شماره تماس، شماره کارت ۱۶رقمی و نام صاحب کارت را ثبت کنید.
- اطلاعات کارت و شماره تماس **عمومی** خواهند بود، پس فقط اطلاعات کسب‌وکار را وارد کنید.
- انتخاب «فعال کردن دریافت سفارش دستی» پیش‌فرض **غیرفعال** است. تنها پس از تست و تکمیل اطلاعات قانونی/ارسال آن را روشن کنید.
- رمز ورود در Cloudflare Secret باقی می‌ماند؛ در پنل هرگز رمز یا API Token وارد نکنید.
- سفارش‌ها در پنل نمایش داده می‌شوند؛ تغییر وضعیت `confirmed` تنها پس از بررسی مستقل واریز در حساب بانکی فروشنده مجاز است.

## ۳. تست با داده غیرواقعی

1. ابتدا تنظیمات را با شماره/حسابی که مالک فروشگاه اجازه داده ثبت کنید؛ سفارش‌ها هنوز خاموش باشند.
2. بررسی کنید روی ویترین راه‌های تماس نمایش داده می‌شوند، اما دکمه ثبت سفارش غیرفعال است.
3. موقتاً سفارش‌ها را فعال کنید؛ یک سبد با دو ترکیب سایز/رنگ بسازید.
4. از `/checkout.html` فرم تست را **با داده غیرواقعی** کامل کنید؛ قیمت باید از سرور محاسبه شود.
5. کد ZS و متن پیام واتساپ/لینک تلگرام را بررسی کنید. انتقال وجه انجام ندهید.
6. فقط یک عکس ساختگی، بدون اطلاعات بانکی حقیقی، به‌عنوان رسید آپلود کنید.
7. با ورود مدیر به پنل، همان سفارش و رسید خصوصی را ببینید؛ وضعیت باید `receipt_submitted` باشد، نه تأیید پرداخت.
8. رسید نباید از مسیر عمومی `/media/receipts/... ` در دسترس باشد.
9. تلاش برای سفارش ناموجود/قیمت دستکاری‌شده باید رد شود. چهار سفارش آزمایشی در ساعت برای هر IP مجاز است؛ پس تست فشرده از یک IP محدود می‌شود.
10. پس از آزمون، **سفارش‌ها را دوباره غیرفعال کنید** و داده‌های تست را طبق نیاز پاک‌سازی کنید.

## ملاحظات راه‌اندازی واقعی

- سفارش اولیه پرداخت نیست. جمع کالاها شامل هزینه ارسال نمی‌شود. فروشنده باید مبلغ نهایی و موجودی را قبل از انتقال وجه تأیید کند.
- شماره کارت فقط در صورت ذخیره شماره ۱۶رقمی معتبر و نام صاحب کارت فعال می‌شود؛ هیچ اطلاعات کارت *مشتری* گرفته نمی‌شود.
- سرور برای سفارش‌ها شناسه تصادفی و محدودیت تعداد بر اساس IP در D1 دارد، اما CAPTCHA/Turnstile و ضداسپم پیشرفته هنوز پیاده‌سازی نشده‌اند.
- رسیدهای مشتری در کلید خصوصی `receipts/*` در KV ذخیره می‌شوند و فقط از API احراز هویت شده مدیر قابل دسترسی هستند.
- انتقال داده‌های مشتری به زیرساخت Cloudflare باید با قوانین و انتظارات حریم خصوصی کسب‌وکار بررسی شود؛ سیاست حفاظت و حذف داده هنوز باید تکمیل شود.
- ممکن است دسترسی از داخل ایران به Cloudflare یا واتساپ/تلگرام محدود شود؛ نسخه آزمایشی را روی چند اپراتور تست کنید.
- سقف رایگان KV: ۱ گیگابایت و ۱۰۰۰ نوشتن در روز، محدودیت فروشگاه باید نظارت شود؛ از خرید/ارتقا بدون نیاز واقعی خودداری کنید.
- ارسال رسید در KV و نگهداری سفارش در D1 جایگزین درگاه بانکی رسمی یا بررسی مقررات مالیاتی نمی‌شود.
